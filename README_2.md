# Architecture Documentation - Kairos Finance 🏛️

This document provides a detailed overview of the system architecture, data flow, and technical components of Kairos Finance.

## 1. System Overview
Kairos Finance follows a **Local-First Client-Server Architecture**. It is designed to run entirely on the user's machine, ensuring data privacy and high performance.

- **Frontend**: A modern React application using Vite for building and development.
- **Backend**: An Express.js server that handles business logic, file parsing, and AI integration.
- **Database**: SQLite (via `better-sqlite3`) for persistent local storage.

---

## 2. Technical Stack

### Frontend
- **Framework**: [React 19](https://react.dev/)
- **Build Tool**: [Vite](https://vitejs.dev/)
- **Styling**: Vanilla CSS with **Glassmorphism** design principles.
- **Charts**: [Recharts](https://recharts.org/) for data visualization.
- **Icons**: [Lucide-React](https://lucide.dev/).
- **Data Fetching**: Axios.

### Backend
- **Framework**: [Express.js](https://expressjs.com/)
- **Runtime**: [Node.js](https://nodejs.org/)
- **Database Driver**: [better-sqlite3](https://github.com/WiseLibs/better-sqlite3).
- **File Processing**: 
    - [Multer](https://github.com/expressjs/multer) (Upload handling).
    - [pdf-parse](https://www.npmjs.com/package/pdf-parse) (PDF extraction).
    - [XLSX (SheetJS)](https://sheetjs.com/) (Excel processing).
- **AI Integration**: OpenAI / Perplexity API for categorization and financial insights.

## 4. Data Flow

The following describes the lifecycle of a transaction from file upload to display:

1.  **File Upload**: The user uploads files (PDF, CSV, XLSX) via the dashboard.
2.  **Parsing**: The `server/parser.ts` extracts raw text or structured data from the files.
3.  **AI Categorization**:
    - The raw data is sent to `server/ai.ts`.
    - It uses the current list of categories and historical mappings (from DB) to categorize each transaction.
4.  **Deduplication**: The server checks if the transactions already exist in the database (based on date, amount, and description).
5.  **Persistence**: Confirmed unique transactions are saved to the `transactions` table in SQLite.
6.  **UI Sync**: The frontend refreshes its state by fetching the updated list of transactions and insights.

## 5. Database Schema

### `accounts`
Stores the financial account names (e.g., "Nubank", "Itaú").
| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | INTEGER | Primary Key (Auto-increment) |
| `name` | TEXT | Unique account name |
| `created_at` | DATETIME | Timestamp of creation |

### `categories`
Customizable list of transaction categories.
| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | INTEGER | Primary Key (Auto-increment) |
| `name` | TEXT | Unique category name |

### `transactions`
The core ledger of the application.
| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | INTEGER | Primary Key (Auto-increment) |
| `account_id` | INTEGER | FK to `accounts.id` |
| `date` | TEXT | Transaction date |
| `description`| TEXT | Original or sanitized description |
| `amount` | REAL | Transaction value |
| `category` | TEXT | Assigned category |
| `type` | TEXT | 'entrada' (income) or 'saida' (expense) |
| `source_file` | TEXT | Reference to the original file |

### `ai_insights`
Summaries and suggestions generated by AI.
| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | INTEGER | Primary Key (Auto-increment) |
| `period` | TEXT | Format: 'YYYY-MM' |
| `content` | TEXT | Markdown content of the insight |
| `type` | TEXT | 'consumption' (analysis) or 'tip' (financial tip) |

## 6. API Reference

### Data Management
- `GET /api/data`: Returns all transactions, insights, and categories.
- `POST /api/upload`: Handles multi-file upload and AI categorization.
- `POST /api/analyze`: Forces a re-analysis of all transactions to update insights.

### Transaction Operations
- `PUT /api/transactions/:id`: Edit description or category.
- `DELETE /api/transactions/:id`: Remove a single record.
- `POST /api/transactions/bulk-delete`: Remove multiple records at once.

### Category Management
- `GET /api/categories`: List all categories.
- `POST /api/categories`: Register a new category.
- `PUT /api/categories/:id`: Rename an existing category.
- `DELETE /api/categories/:id`: Delete a category.

## 7. Security & Privacy

> [!IMPORTANT]
> **Privacy is a core pillar of Kairos Finance.**
> - All transaction data is stored locally in an unencrypted SQLite database.
> - No transaction data is sent to external servers except for the temporary processing of descriptions during AI categorization (via OpenAI/Perplexity API).
> - API keys should be stored in the root `.env` file and **never** committed to version control.
